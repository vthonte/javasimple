Spring IoC Container, Bean Scopes & Lifecycle Hooks

How the ApplicationContext creates and wires beans: Singleton vs Prototype vs Request scopes, BeanFactoryPostProcessor vs BeanPostProcessor, and solving Circular Dependency deadlocks.

💡

ELI5: The Smart Factory Assembly Floor

In standard programming, when Worker A needs a drill, Worker A runs to the hardware store and buys a drill with new Drill(). If 500 workers need drills, you end up with 500 duplicate drills wasting money and memory.

The Spring IoC Container (Inversion of Control) is the factory floor manager. At startup, it creates one central heavy-duty tool rack (ApplicationContext) holding single instances of tools. When Worker A reports for work, the manager hands Worker A the existing shared tool directly through the constructor.

📊 The 5 Spring Bean Scopes Explained

Scope Lifecycle / Lifetime Thread Safety Rule Common Usage
Singleton (Default) 1 instance per Spring ApplicationContext. MUST BE STATELESS! (Shared across all threads) @Service, @Repository, @RestController, Clients.
Prototype A brand new instance created every single time injected. Thread-safe if not shared. Stateful user sessions, mutable calculation contexts.
Request (Web) 1 instance per incoming HTTP request. Destroyed at response. Safe for that single HTTP thread. Request tracing headers, tenant ID context.

Senior Architecture: Circular Dependencies

The Problem: Service A needs B, Service B needs A Fatal Startup Error

In Spring Boot 2.6+, circular dependencies are strictly disabled by default because they signal poor architectural separation of concerns. 

// ❌ CIRCULAR DEADLOCK: Application fails to start!
@Service
public class OrderService {
    private final PaymentService paymentService;
    public OrderService(PaymentService paymentService) { this.paymentService = paymentService; }
}

@Service
public class PaymentService {
    private final OrderService orderService; // Needs OrderService!
    public PaymentService(OrderService orderService) { this.orderService = orderService; }
}
✅ Senior Clean Architecture Fix: Extract the shared behavior into a third independent coordinator bean (e.g., OrderPaymentOrchestrator) or use an asynchronous domain event (ApplicationEventPublisher) to decouple the two services!
