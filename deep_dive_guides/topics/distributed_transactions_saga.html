Distributed Transactions: The Dual-Write Problem, Transactional Outbox & Saga Pattern

Why 2-Phase Commit (2PC) fails in cloud microservices: solving the Dual-Write trap using PostgreSQL WAL + Debezium CDC, and implementing Choreography vs Orchestration Sagas with compensating transactions.

💡

ELI5: The Travel Booking Trip (Sagas)

You book a vacation that requires 3 steps: Flight, Hotel, and Rental Car. Each belongs to a different company (different microservices with separate databases). You cannot wrap all 3 in a single SQL transaction.

The Saga Pattern is a series of local transactions. Flight is booked successfully. Hotel is booked successfully. But the Rental Car is sold out! The Saga initiates Compensating Transactions: it automatically sends messages to cancel the Hotel reservation and refund the Flight ticket, returning the system to a clean, consistent state!

📬 The Transactional Outbox Pattern in Code

Instead of calling Kafka inside your transaction, insert the event into an outbox table in the same DB transaction: 

@Transactional
public OrderDTO createOrder(CreateOrderRequest req) {
    // 1. Insert into orders table
    Order order = orderRepository.save(new Order(req.userId(), req.amount()));

    // 2. Insert into outbox table in the SAME transaction!
    OutboxEvent event = new OutboxEvent(
        "OrderCreated",
        order.getId().toString(),
        objectMapper.writeValueAsString(new OrderCreatedPayload(order.getId(), req.userId()))
    );
    outboxRepository.save(event);

    return new OrderDTO(order.getId());
    // Both commit atomically! Zero chance of dual-write corruption!
}

Saga Architecture: Choreography vs. Orchestration

Choreography (Event-Driven)

Services listen to events and decide next action autonomously. No central coordinator. Simple for 2-3 services, but difficult to track workflows when > 5 services interact.

Orchestration (Workflow Engine)

A central orchestrator (e.g. Temporal, Camunda, or Spring StateMachine) coordinates calls, tracks status, and handles rollbacks explicitly. Clear visibility into business transactions.
