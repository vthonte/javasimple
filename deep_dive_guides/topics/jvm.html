JVM Architecture, Classloaders & JIT Compilation (C1/C2)

Under the hood of the Java Virtual Machine: ClassLoader hierarchy, bytecode verification, Interpreter vs JIT Compiler (Tiered Compilation), and On-Stack Replacement (OSR).

💡

ELI5: The Universal Translator and Speed Reader

When you run node app.js, V8 translates JS directly to machine code. The JVM does something smarter: it compiles Java code to universal Bytecode (compact instructions).

At startup, the JVM Interpreter starts reading bytecode immediately (fast startup). Meanwhile, a background profiler counts method calls. When a method is called 10,000 times ("Hot Spot"), the JIT Compiler (C2) kicks in, translates that exact method directly into raw Intel/ARM assembly, inlines functions, unrolls loops, and runs it faster than native C++!

📊 ClassLoader Delegation Hierarchy

1. Bootstrap ClassLoader (C++ Native)

Loads core JDK classes (java.lang.*, java.util.*) from lib/modules.

↓ delegates child if not found ↓
2. Platform / Extension ClassLoader

Loads extended JDK modular features (SQL, XML, Logging).

↓ delegates child if not found ↓
3. Application / System ClassLoader

Loads your application classes from CLASSPATH and Maven JAR dependencies.

Inspecting Raw Bytecode (javap)

You can inspect the exact instructions the JVM executes using JDK's built-in disassembler:

# Compile and disassemble:
javac UserService.java
javap -c -v UserService.class
// Sample output showing stack instructions:
0: aload_0 // push 'this' onto operand stack
1: invokespecial #1 // Method java/lang/Object."<init>":()V
4: return
