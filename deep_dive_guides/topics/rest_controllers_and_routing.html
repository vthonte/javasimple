Building REST APIs: Express.js vs. Spring Boot @RestController

Direct side-by-side comparison of API routing, request validation (Joi vs Jakarta Validation), path variables, request params, and Jackson JSON serialization.

💡

ELI5: The Reception Desk & Security Guard

In Express, you write imperatively: check if body is missing, manually send 400 status, parse parameters manually. In Spring Boot, you write declaratively with annotations.

A @RestController is the reception desk. By adding @Valid, a security guard checks the incoming payload before your method ever runs. If the email is invalid or age is negative, Spring rejects it instantly with a 400 Bad Request!

Side-by-Side: Building a User Management API

Node.js (Express + Joi) Imperative 
const express = require('express');
const router = express.Router();

// GET /api/users/:id?details=true
router.get('/:id', async (req, res) => {
  const { id } = req.params;
  const showDetails = req.query.details === 'true';

  const user = await userService.findById(id);
  if (!user) return res.status(404).json({ error: 'Not found' });
  return res.json(user);
});

// POST /api/users
router.post('/', async (req, res) => {
  // Manual Joi validation
  const { error } = userSchema.validate(req.body);
  if (error) return res.status(400).json({ error: error.message });

  const newUser = await userService.create(req.body);
  return res.status(201).json(newUser);
});

module.exports = router;
Spring Boot (@RestController) Declarative 
@RestController
@RequestMapping("/api/users")
public class UserController {

  private final UserService userService;
  public UserController(UserService service) { this.userService = service; }

  // GET /api/users/{id}?details=true
  @GetMapping("/{id}")
  public ResponseEntity<UserDTO> getUser(
      @PathVariable Long id,
      @RequestParam(defaultValue = "false") boolean details) {
    return ResponseEntity.ok(userService.findById(id));
  }

  // POST /api/users with automatic @Valid validation!
  @PostMapping
  @ResponseStatus(HttpStatus.CREATED)
  public UserDTO createUser(@Valid @RequestBody CreateUserRequest req) {
    return userService.create(req);
  }
}

Request Validation (Jakarta Validation)

Instead of writing manual if (!req.body.email) statements, annotate your DTO record:

public record CreateUserRequest(
    @NotBlank(message = "Username cannot be empty")
    @Size(min = 3, max = 50, message = "Username must be 3-50 chars")
    String username,

    @NotBlank(message = "Email is required")
    @Email(message = "Must be a valid email format")
    String email,

    @Min(value = 18, message = "Must be at least 18 years old")
    int age
) {}
