Java Platform Threads & Thread Pools (ThreadPoolExecutor)

The classical 1:1 OS thread model: thread lifecycle, OS kernel scheduling, ThreadPoolExecutor internals, race conditions, and synchronizers (CountDownLatch, Semaphore).

💡

ELI5: The 1:1 Kernel Mapping

Unlike Node (1 process doing cooperative async), a traditional Java thread is literally a real Linux/Windows operating system thread. When you call new Thread().start(), the JVM asks the Linux kernel to allocate a 1MB native stack and register the thread with the OS CPU scheduler.

Because OS threads are expensive to create, Java uses Thread Pools: hire 20 workers once, keep them alive forever, and feed them tasks via a queue!

📊 ThreadPoolExecutor Task Rejection Flowchart

1 Task arrives → If running threads < corePoolSize: Spawn new thread.
2 If corePoolSize reached → Add task to BlockingQueue.
3 If queue is FULL → Spawn extra threads up to maximumPoolSize.
4 If max threads reached & queue is full → Trigger RejectedExecutionHandler (Crash or CallerRunsPolicy)!

Custom Production Thread Pool Configuration

Production Ready

Configuring ThreadPoolExecutor Safely

ThreadPoolExecutor executor = new ThreadPoolExecutor(
    10,                         // core pool size
    50,                         // max pool size
    60L, TimeUnit.SECONDS,      // keep alive time for idle threads
    new ArrayBlockingQueue<>(1000), // bounded queue (NEVER use unbounded in prod!)
    new ThreadFactoryBuilder().setNameFormat("order-proc-%d").build(),
    new ThreadPoolExecutor.CallerRunsPolicy() // backpressure: caller runs task instead of dropping!
);
Coordination Primitives

Waiting for Multiple Threads: CountDownLatch

The Java equivalent of waiting for a batch of async jobs:

CountDownLatch latch = new CountDownLatch(3);

for (int i = 0; i < 3; i++) {
    executor.submit(() -> {
        try {
            processTask();
        } finally {
            latch.countDown(); // decrements counter
        }
    });
}

latch.await(5, TimeUnit.SECONDS); // Blocks until all 3 finish or timeout!
