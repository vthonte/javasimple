JVM Memory Management (Stack vs Heap vs Metaspace)

Deep dive into memory layout: Young Generation (Eden, Survivor S0/S1), Old Generation (Tenured), Object Header memory overhead (Mark Word & Klass Word), and ThreadLocal memory leaks.

🔬 Pro Concept: The Hidden Cost of Java Objects (Object Header)

In Node.js or C++, a 32-bit integer is just 4 bytes. In Java, if you allocate an Integer object (boxed), it consumes 16 bytes minimum on a 64-bit JVM due to object overhead:

Mark Word (8 bytes)

Identity hashCode, GC age bits (0-15), locking state (biased, thin, fat lock)

Klass Pointer (4-8 bytes)

Pointer to the metadata class in Metaspace (+Compressed OOPs)

Instance Data (4 bytes)

The actual primitive int value = 42;

💡 Senior Takeaway: Use primitive types (int, long, double) whenever possible instead of Boxed objects (Integer, Long, Double) in high-throughput data pipelines to avoid 4x memory inflation and GC pressure!

📊 Object Lifecycle: Eden to Old Generation Promotion

1. Eden Space (Young Gen)

All new objects created via new land here. Fast allocation via Thread-Local Allocation Buffers (TLAB).

↓ Minor GC (Survivor of collection) ↓
2. Survivor Spaces (S0 / S1)

Bounces between From-Space and To-Space. Each survival increments GC age counter.

↓ Tenuring Threshold reached (default age 15) ↓
3. Tenured (Old Generation)

Long-lived objects (Spring Singletons, Cache entries). Cleaned during Major/Mixed GC.

Senior Production Trap: The ThreadLocal Memory Leak

In Spring Boot/Tomcat, worker threads are pooled and reused for thousands of HTTP requests. If you store user authentication or request context in a ThreadLocal and forget to call .remove() in a finally block, that object remains attached to the pooled thread indefinitely, resulting in a silent OutOfMemoryError in production! 

// ✅ ALWAYS wrap ThreadLocal cleanup in a try-finally block!
public static final ThreadLocal<UserContext> CONTEXT = new ThreadLocal<>();

public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain) {
    try {
        CONTEXT.set(loadUser(req));
        chain.doFilter(req, res);
    } finally {
        CONTEXT.remove(); // CRITICAL: Prevents memory leak in thread pool!
    }
}
