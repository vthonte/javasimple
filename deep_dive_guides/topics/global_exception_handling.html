Global Exception Handling: @RestControllerAdvice vs Express Error Middleware

Why writing try/catch blocks in every controller method is an anti-pattern: using @RestControllerAdvice, custom runtime exceptions, and implementing the modern RFC 7807 ProblemDetail standard.

💡

ELI5: The Express Error Middleware Sister

In Express, when a route throws an error or calls next(err), execution bypasses all normal routes and jumps straight into your 4-argument global error handler: app.use((err, req, res, next) => ...).

Spring Boot's @RestControllerAdvice is the exact same thing! Any exception thrown anywhere in your Service, Repository, or Controller layer bubbles up and gets caught by a central class that formats a clean JSON error response for the client.

📊 Exception Interception Pipeline

1. Service Layer throw new ResourceNotFoundException("User 42 not found")
→ Uncaught Exception →
2. @RestControllerAdvice @ExceptionHandler(ResourceNotFoundException.class)

Intercepts error before Tomcat 500 response

→ Formats JSON →
3. HTTP 404 Client Response { "status": 404, "error": "Not Found" }

Production Implementation in Spring Boot 3

Standard RFC 7807 Pattern

GlobalExceptionHandler.java

@RestControllerAdvice
public class GlobalExceptionHandler {

    // 1. Handle Custom Business Exceptions (e.g. 404 Not Found)
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ProblemDetail> handleNotFound(ResourceNotFoundException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.NOT_FOUND, ex.getMessage()
        );
        problem.setTitle("Resource Not Found");
        problem.setProperty("timestamp", Instant.now());
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(problem);
    }

    // 2. Handle Validation Errors (@Valid DTO failure -> 400 Bad Request)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handleValidation(MethodArgumentNotValidException ex) {
        Map<String, String> errors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(error -> 
            errors.put(error.getField(), error.getDefaultMessage())
        );
        return ResponseEntity.badRequest().body(errors);
    }

    // 3. Fallback for unexpected server bugs (500 Internal Server Error)
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ProblemDetail> handleGlobal(Exception ex) {
        // Log stack trace internally, never leak raw DB/internal details to client!
        logger.error("Unhandled server exception", ex);
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.INTERNAL_SERVER_ERROR, "An unexpected error occurred"
        );
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(problem);
    }
}
