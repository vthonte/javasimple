The Node.js Event Loop & libuv Architecture

How single-threaded Node.js handles thousands of concurrent connections: the 6 phases of the libuv event loop, microtask queues, process.nextTick priority, and threadpool blocking traps.

💡

ELI5: The Airport Luggage Carousel

Imagine a luggage carousel that circles continuously through 6 stations. Passengers (timers, I/O callbacks, close handlers) place bags onto specific stations. The carousel operator (the single main thread) checks each station one-by-one, empties the ready bags, and immediately rotates to the next station.

The danger: If one passenger asks the operator to solve a complex Rubik's cube (CPU intensive hashing or JSON parsing), the operator stops the entire carousel. Every other passenger in the airport waits and starves!

📊 The 6 Phases of libuv Event Loop

1. Timers

Executes expired setTimeout() and setInterval() callbacks.

2. Pending Callbacks

Executes I/O callbacks deferred to the next loop iteration (TCP errors, etc).

3. Idle, Prepare

Internal libuv housekeeping only.

4. Poll (Heart of Node)

Retrieves new I/O events (incoming HTTP requests, socket reads). Waits here if idle!

5. Check

Executes setImmediate() callbacks immediately after poll.

6. Close Callbacks

Executes cleanup e.g., socket.on('close', ...).

⚡ Microtask Priority: Between EVERY single phase, Node checks the nextTickQueue (process.nextTick) and the MicrotaskQueue (Promise.then). They execute BEFORE the loop moves to the next phase!

Code Labs & Production Pitfalls

Senior Trap #1

Blocking the Event Loop with Synchronous Operations

// ❌ DANGEROUS: Freezes the entire server for all users!
app.post('/hash', (req, res) => {
  // Sync crypto or giant JSON.parse blocks the main thread
  const hash = crypto.pbkdf2Sync(req.body.password, 'salt', 100000, 64, 'sha512');
  res.json({ hash: hash.toString('hex') });
});

// ✅ SENIOR FIX: Asynchronous version uses libuv threadpool (default 4 threads)
app.post('/hash', (req, res) => {
  crypto.pbkdf2(req.body.password, 'salt', 100000, 64, 'sha512', (err, key) => {
    res.json({ hash: key.toString('hex') });
  });
});
Senior Production Tuning

Scaling libuv Threadpool (UV_THREADPOOL_SIZE)

Node uses a background C++ threadpool for: fs.* file operations, crypto.* hashing, and dns.lookup(). The default size is only 4 threads! If 5 users upload files or hash passwords at once, the 5th request is queued. 

# Increase libuv worker threads in production Docker / Kubernetes:
export UV_THREADPOOL_SIZE=64
node server.js
