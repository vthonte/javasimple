Spring AOP & Dynamic Proxies (JDK Dynamic vs CGLIB)

How Spring weaves cross-cutting concerns: Pointcuts, JoinPoints, Advices, JDK Dynamic Proxies (interface-based) vs CGLIB (subclass bytecode generation), and why final classes break proxying.

💡

ELI5: The Stunt Double (Dynamic Proxies)

When an action movie star (your Service class) has a dangerous scene involving fire and stunts (database transactions, caching, security checks), the movie director hires a Stunt Double (CGLIB Proxy).

The audience (the HTTP Controller) thinks they are calling the real actor. But in reality, the Stunt Double steps in front of the camera, opens the safety nets (tx.begin()), lets the actor do the real talking, and secures the landing (tx.commit()).

⚖️ JDK Dynamic Proxies vs. CGLIB Subclassing

JDK Dynamic Proxies (Reflection)

• Requires an interface (UserService interface implemented by UserServiceImpl).
• Built into core Java (java.lang.reflect.Proxy).
• Cannot proxy concrete classes without interfaces.

CGLIB Proxies (Spring Boot Default)

• Generates a new subclass in bytecode at runtime (UserService$$EnhancerBySpringCGLIB).
• Works on concrete classes with no interfaces!
• Limitation: Cannot proxy final classes or final methods!

Code Lab: Building a Performance Timing Aspect

@Aspect
@Component
public class ExecutionTimeAspect {

    private final Logger logger = LoggerFactory.getLogger(ExecutionTimeAspect.class);

    // Intercepts any method inside com.example.service package!
    @Around("execution(* com.example.service..*(..))")
    public Object measureExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        
        // Execute the target method (calls real bean logic)
        Object result = joinPoint.proceed();
        
        long duration = System.currentTimeMillis() - start;
        logger.info("Method {} executed in {} ms", joinPoint.getSignature().toShortString(), duration);
        
        return result;
    }
}
