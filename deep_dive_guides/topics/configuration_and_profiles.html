Configuration, Environment Variables & Profiles (Node .env vs Spring YAML)

How Spring Boot loads configuration: application.properties vs application.yml, switching environments with Profiles (dev vs stage vs prod), and type-safe binding with @ConfigurationProperties.

💡

ELI5: The Chameleon's Wardrobe (Spring Profiles)

In Node, you usually have .env.development and .env.production loaded by dotenv.

Spring Boot has native, built-in Profiles. You create application-dev.yml (connecting to localhost Postgres) and application-prod.yml (connecting to AWS RDS). By passing a single environment variable SPRING_PROFILES_ACTIVE=prod, Spring changes its entire behavior without changing a single line of Java code!

Type-Safe Configuration: The Senior Way

In Node, developers read raw strings with process.env.JWT_SECRET, risking runtime crashes if misspelled. In Spring Boot, you bind entire YAML blocks to a strongly typed Java class:

application.yml
app:
  jwt:
    secret-key: "my-super-secret-key-that-is-very-long"
    expiration-ms: 86400000 # 24 hours
  stripe:
    api-key: "sk_test_12345"
    timeout-seconds: 5
JwtProperties.java (@ConfigurationProperties)
@ConfigurationProperties(prefix = "app.jwt")
@Validated
public record JwtProperties(
    @NotBlank String secretKey,
    @Positive long expirationMs
) {}

If the secret key is missing or expiration is negative, the app fails fast at boot with a clear error!

Relaxed Binding: Overriding YAML in Kubernetes

Spring Boot supports Relaxed Binding. You don't need to touch the YAML file in production; just set an uppercase environment variable in Docker or Kubernetes:

YAML property: app.jwt.secret-key
Linux / Docker Env Var: APP_JWT_SECRET_KEY=prod-secret
YAML property: spring.datasource.password
Linux / Docker Env Var: SPRING_DATASOURCE_PASSWORD=db-password
