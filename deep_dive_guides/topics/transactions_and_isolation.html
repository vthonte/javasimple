Transaction Management: Propagation, Isolation Levels & Rollback Rules

How Spring manages database transactions: why checked exceptions do NOT trigger rollback by default, REQUIRED vs REQUIRES_NEW propagation, dirty reads vs phantom reads, and Optimistic Locking (@Version) vs Pessimistic Locking.

💡

ELI5: The Bank Vault & The Notary Public

When you transfer \$100 from Account A to Account B, you step into a secure bank vault with a Notary (@Transactional). Both ledger updates must happen. If a robber bursts in before B is credited, the Notary tears up the papers (ROLLBACK) so A never loses their money.

The catch: If the Notary hears a minor noise (a Java Checked Exception), by default the Notary says: "That wasn't fatal, let's keep the transaction!" You must explicitly tell Spring: @Transactional(rollbackFor = Exception.class) to protect against ALL errors!

🔄 Propagation: REQUIRED vs. REQUIRES_NEW

Propagation.REQUIRED (Default)

"Join existing transaction if one exists; create new one if none."
If Child method fails, Parent transaction is marked rollback-only!

Propagation.REQUIRES_NEW

"Suspend parent transaction, open an independent second physical DB connection, commit independently, then resume parent."
Best use: Audit logs that must save even if payment rolls back!

Preventing Lost Updates: Optimistic vs Pessimistic Locking

1. Optimistic Locking (@Version)

Zero DB locks! Adds a version integer column. When updating: WHERE id = ? AND version = 1. If another thread beat you to it, version is 2, and Hibernate throws OptimisticLockException. High throughput!

@Entity
public class Product {
    @Id private Long id;
    private int stock;
    
    @Version
    private int version; // Auto-incremented by Hibernate!
}
2. Pessimistic Locking (SELECT FOR UPDATE)

Locks the database row immediately in PostgreSQL. Other transactions wait until this transaction completes. High safety, lower concurrency.

public interface ProductRepository extends JpaRepository<Product, Long> {
    @Lock(LockModeType.PESSIMISTIC_WRITE)
    @Query("SELECT p FROM Product p WHERE p.id = :id")
    Optional<Product> findByIdForUpdate(Long id);
}
