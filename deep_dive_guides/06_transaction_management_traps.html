Transaction Management in Code: Node.js Transactions vs. Spring @Transactional

Let's compare how manual ACID transactions are written in Node.js (Prisma/Knex) versus Spring's declarative @Transactional, and see the exact CGLIB proxy bypass bug in code.

1 Code Lab 1: Bank Transfer (Deduct from A, Credit to B)

Node.js (Prisma $transaction closure)
async function transferMoney(fromId, toId, amount) {
  // Prisma $transaction: Executes all steps inside 1 DB transaction
  return await prisma.$transaction(async (tx) => {
    // 1. Deduct from sender
    const sender = await tx.account.update({
      where: { id: fromId },
      data: { balance: { decrement: amount } }
    });

    if (sender.balance < 0) {
      // Throwing error inside closure triggers automatic ROLLBACK
      throw new Error('Insufficient funds!');
    }

    // 2. Credit to receiver
    const receiver = await tx.account.update({
      where: { id: toId },
      data: { balance: { increment: amount } }
    });

    return { sender, receiver };
  });
}
Java Spring Boot (@Transactional)
@Service
public class BankTransferService {

    private final AccountRepository accountRepo;

    public BankTransferService(AccountRepository repo) {
        this.accountRepo = repo;
    }

    // Declarative transaction wrapping the whole method:
    @Transactional(rollbackFor = Exception.class)
    public void transferMoney(Long fromId, Long toId, BigDecimal amount) {
        Account sender = accountRepo.findById(fromId).orElseThrow();
        Account receiver = accountRepo.findById(toId).orElseThrow();

        sender.deduct(amount);
        receiver.credit(amount);

        // If an exception is thrown anywhere here, 
        // the Spring CGLIB proxy intercepts it and rolls back both updates!
    }
}

2 Code Lab 2: The Self-Invocation Bug & The 2 Senior Refactoring Solutions

âŒ The Broken Code (Self-Invocation):
@Service
public class OrderService {

    public void processOrder(Order order) {
        validateCart(order);
        // Direct call to another method in the same class!
        this.saveOrderWithAudit(order); // <-- PROXY BYPASSED! @Transactional IGNORED!
    }

    @Transactional
    public void saveOrderWithAudit(Order order) {
        orderRepo.save(order);
        auditRepo.save(new AuditLog("ORDER_CREATED"));
    }
}

Why: Spring creates a proxy around the bean. When processOrder is called, execution enters the real object. Inside the real object, this points to the plain Java instance, not the proxy wrapper!

âœ… Senior Solution 1: Clean Architectural Separation
@Service
public class OrderService {
    // Inject the dedicated transactional collaborator:
    private final OrderWriterService orderWriter;

    public OrderService(OrderWriterService writer) {
        this.orderWriter = writer;
    }

    public void processOrder(Order order) {
        validateCart(order);
        // Crosses Spring Bean boundary -> Hits the Proxy -> @Transactional works!
        orderWriter.saveOrderWithAudit(order); 
    }
}
âœ… Senior Solution 2: Programmatic TransactionTemplate
@Service
public class OrderService {
    private final TransactionTemplate txTemplate;

    public OrderService(TransactionTemplate tx) {
        this.txTemplate = tx;
    }

    public void processOrder(Order order) {
        validateCart(order);
        // Explicit closure (works exactly like Prisma $transaction!)
        txTemplate.executeWithoutResult(status -> {
            orderRepo.save(order);
            auditRepo.save(new AuditLog("ORDER_CREATED"));
        });
    }
}
