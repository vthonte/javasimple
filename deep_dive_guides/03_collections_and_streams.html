Java Collections Framework Internals, Thread-Safe Concurrency & Streams API

Why HashMap is not thread-safe, how bucket collisions and treeification work, when to choose ConcurrentHashMap, and how Java 8+ Streams differ from JavaScript array methods.

1 The Java Collections Architecture Overview

In JavaScript, you almost exclusively use Array, Object, and Set. In Java, the Collections Framework is divided into interfaces with specialized, performance-tuned implementations:

List<E> (Ordered Collection)

Allows duplicates. Preserves insertion order.

  • ArrayList: Backed by resizable array. $O(1)$ random index access. Best default choice for 99% of lists.
  • LinkedList: Doubly-linked node pointers. $O(1)$ insert/remove at head/tail. $O(N)$ random access. High memory overhead per node pointer.
Set<E> (Unique Collection)

Disallows duplicates. Fast membership checking.

  • HashSet: Backed by a HashMap where values are dummy objects. $O(1)$ contains(). Unordered.
  • TreeSet: Backed by Red-Black tree. Keeps elements sorted in natural or comparator order. $O(\log N)$ operations.
Map<K, V> (Key-Value Dictionary)

Does not extend Collection, but part of framework.

  • HashMap: Fast, non-thread-safe dictionary.
  • ConcurrentHashMap: Thread-safe, lock-free reads, segment striped locks on write.
  • LinkedHashMap: Preserves insertion order of keys.

2 HashMap Internals: The #1 Java Core Interview Question

Interviewers will ask: "Explain how map.put(key, value) and map.get(key) work internally."

Step 1: Hash Calculation

Java calls key.hashCode() and applies bitwise XOR spreading to reduce collision clustering. The array bucket index is calculated via: index = (n - 1) & hash (where $n$ is table capacity, always a power of 2).

Step 2: Collision Handling (Chaining)

If the bucket is empty, a new Node(hash, key, value, null) is stored. If a node already exists (hash collision), Java traverses the linked list, checking key.equals(existingKey). If found, it updates value; otherwise it appends to the list.

Step 3: Treeification (Java 8+ Optimization)

If collisions cause a bucket list length to exceed 8 elements (and total table size $\ge 64$), Java automatically converts the linked list into a Red-Black Balanced Binary Search Tree! This turns worst-case lookup from degraded $O(N)$ into guaranteed $O(\log N)$.

Why HashMap fails catastrophically under multi-threading:

HashMap is not synchronized. If two threads call put() simultaneously during resizing (rehash), it causes race conditions, corrupted pointer links, or an infinite loop that pins CPU at 100%. In multi-threaded Spring services, always use ConcurrentHashMap.

3 Java Streams API vs JavaScript Functional Array Methods

JavaScript Array Pipelines (Eager)
const results = items
  .filter(x => x.price > 100)  // creates array #1 in RAM
  .map(x => x.name)            // creates array #2 in RAM
  .slice(0, 5);                // creates array #3 in RAM

In Node.js, each chained function executes immediately on the entire collection and allocates an intermediate array in memory.

Java Streams (Lazy & Single Pass)
List<String> results = items.stream()
  .filter(x -> x.getPrice() > 100) // intermediate (lazy)
  .map(Item::getName)             // intermediate (lazy)
  .limit(5)                       // intermediate (short-circuit)
  .toList();                      // terminal (triggers work)

Java Streams do zero work until the terminal operator (.toList(), .collect(), .count()) is invoked. Elements flow through filter $\rightarrow$ map one at a time, stopping as soon as 5 matches are found! Zero intermediate arrays.
