Dependency Injection in Code: Express.js vs. NestJS vs. Spring Boot

Let's inspect how dependencies are created and injected across Node.js (manual/Express), TypeScript (NestJS), and modern Spring Boot with constructor injection.

1 Code Lab 1: Wiring Controller → Service → Repository

1. Node.js (Express - Manual Factory / Imports) No Built-in Container 
// user.service.js
import db from '../db.js';
import emailClient from '../mailer.js';

class UserService {
  constructor(database = db, mailer = emailClient) {
    this.db = database; // manual default assignment
    this.mailer = mailer;
  }

  async registerUser(email) {
    const user = await this.db.users.create({ data: { email } });
    await this.mailer.sendWelcomeEmail(email);
    return user;
  }
}

// user.controller.js
const userService = new UserService(); // Developer manually instantiates singletons!
router.post('/register', (req, res) => userService.registerUser(req.body.email));
2. Node.js (NestJS - TypeScript IoC Container) Reflection-based DI (Inspired by Spring!) 
// user.service.ts
@Injectable()
export class UserService {
  constructor(
    private readonly userRepo: UserRepository,
    private readonly mailer: MailerService
  ) {}

  async registerUser(email: string) {
    const user = await this.userRepo.create(email);
    await this.mailer.sendWelcome(email);
    return user;
  }
}

// user.controller.ts
@Controller('users')
export class UserController {
  constructor(private readonly userService: UserService) {} // NestJS auto-injects!

  @Post('register')
  register(@Body('email') email: string) {
    return this.userService.registerUser(email);
  }
}
3. Spring Boot (Modern Java 21 - Constructor Injection) Enterprise Production Standard 
// 1. Service Layer
@Service
public class UserService {
    private final UserRepository userRepository;
    private final MailerService mailerService;

    // Notice: NO @Autowired needed! Spring 4.3+ automatically injects constructor params
    public UserService(UserRepository userRepository, MailerService mailerService) {
        this.userRepository = userRepository;
        this.mailerService = mailerService;
    }

    public User registerUser(String email) {
        User user = userRepository.save(new User(email));
        mailerService.sendWelcome(email);
        return user;
    }
}

// 2. Controller Layer
@RestController
@RequestMapping("/api/users")
public class UserController {
    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping("/register")
    public ResponseEntity<User> register(@RequestBody RegisterRequest req) {
        return ResponseEntity.ok(userService.registerUser(req.email()));
    }
}
Why NestJS and Spring look identical: NestJS was explicitly designed by copying Spring Framework's architecture! If you understand NestJS DI, you already understand 95% of Spring's IoC container.

2 Code Lab 2: Lifecycle Callbacks (@PostConstruct & @PreDestroy)

In Node.js, you initialize resources right at startup in index.js. In Spring, beans manage their own startup and shutdown cleanly: 

@Component
public class CacheWarmerManager {

    private final RedisTemplate<String, String> redisTemplate;
    private final ProductRepository productRepo;

    public CacheWarmerManager(RedisTemplate<String, String> redis, ProductRepository repo) {
        this.redisTemplate = redis;
        this.productRepo = repo;
    }

    // Runs automatically AFTER dependency injection completes on startup:
    @PostConstruct
    public void warmPopularProductsCache() {
        log.info("Warming up product cache on startup...");
        List<Product> topProducts = productRepo.findTop100ByOrderByPopularityDesc();
        topProducts.forEach(p -> redisTemplate.opsForValue().set("prod:" + p.getId(), p.toJson()));
        log.info("Product cache successfully warmed!");
    }

    // Runs automatically when application receives SIGTERM (graceful shutdown in K8s):
    @PreDestroy
    public void flushAndDisconnect() {
        log.info("Graceful shutdown received. Flushing write buffers...");
        redisTemplate.getConnectionFactory().getConnection().flushDb();
        log.info("Shutdown completed safely.");
    }
}
