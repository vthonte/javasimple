Deep Dive 04 • Enterprise Spring Framework

Spring Inversion of Control (IoC), Bean Lifecycle & Dependency Injection Patterns

Understand how the Spring ApplicationContext manages object lifecycles, why Constructor Injection is strictly preferred over @Autowired field injection, and how Bean Scopes behave in multi-threaded web applications.

1 Inversion of Control (IoC): Why You Never Call new Service()

In traditional code, class A decides when and how to instantiate class B:

Traditional Tight Coupling
public class OrderController {
    // Controller creates its own dependency!
    private PaymentService paymentService = new StripePaymentService();
    // Cannot mock in unit tests!
    // Cannot swap with PayPal without changing code!
}
Spring Inversion of Control (IoC)
@RestController
public class OrderController {
    private final PaymentService paymentService;

    // Spring's IoC container passes the instance in!
    public OrderController(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

2 The Complete Spring Bean Lifecycle (Step-by-Step)

1
Component Scanning & Metadata Parsing

Spring scans packages for @Component, @Service, @Repository, @RestController and creates BeanDefinition objects.

2
Instantiation

The JVM invokes the class constructor using reflection. Dependencies are resolved from the IoC container graph.

3
Populate Properties & Awareness Interfaces

Spring injects @Value configurations and satisfies ApplicationContextAware / BeanNameAware if implemented.

4
@PostConstruct Initialization Callback

Methods annotated with @PostConstruct execute immediately after dependencies are wired. Use this to warm local caches, verify third-party connections, or prepare data.

5
Ready to Serve Traffic

The bean is stored in the ApplicationContext singleton cache and handles live incoming HTTP and business calls.

6
@PreDestroy Destruction Callback

When the Spring Boot application shuts down (SIGTERM in Kubernetes / Docker), methods annotated with @PreDestroy execute for graceful cleanup (closing thread pools, flushing buffers, disconnecting sockets).

3 Spring Bean Scopes (Crucial for Multi-Threading)

Singleton (Default)

Only 1 instance per Spring IoC Container. Shared across all concurrent HTTP requests. Must be stateless! If you store user-specific mutable state in a field, requests will overwrite each other's data!

Prototype

A new instance is created every time the bean is requested from the container. Useful for stateful objects that should not be shared across threads.

Request & Session (Web)

@RequestScope creates a bean bound to the lifecycle of a single HTTP request. Destroyed when the HTTP response completes.
